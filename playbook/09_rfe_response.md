# 09 RFE 应对：从收到通知到寄出完整回复

RFE（Request for Evidence）不是拒信，而是官员告诉你"记录里缺什么"。回复的质量取决于
是否**逐条**回应了官员的具体 finding，而不是加了多少页。法律依据见
[02_legal_standard.md](02_legal_standard.md)；模板在 `case-template/rfe-template/`。

## 0. 第一天：建档，不写作

1. 保存原件：在线账户下载的 PDF（或纸质原件 + 信封）放入忽略的
   `source_documents/`；通知含身份信息和地址，不进 Git。
2. 复制 `case-template/rfe-template/` 到 `cases/<id>/rfe-<notice-date>/`。已递交的
   `workproduct/` 和证据保持冻结（[AGENTS.md](../AGENTS.md) Guardrail 5）。
3. 逐页通读（必要时 OCR 后**人工**逐字核对），填 README 的期限表。
4. 先不要发信、不要起草论证：先把通知拆成表（第 1 节）。

## 1. 把每一条 finding 拆成表

在 `02_Response_Map.md` 中，按通知顺序列出：

- **哪些要件已成立**（如 advanced degree、substantial merit）——回复中一句话确认，
  不再重复论证，也不要无意中重新打开它们。
- **每一句被质疑的话**：逐字引用 + 通知页码。通知里列举的"可提交的证据类型"
  清单，每一项也单独成行，即使你不依赖它（写"Not relied on"）。这样官员能看到你
  没有跳过任何一条。
- 每行分类：**事实缺口**（缺证据）/ **法律标准问题**（官员套用了不属于该要件的
  标准）/ **证据被忽略**（你已提交但通知没提到）/ **酌情顾虑**。
- 每行写一句话答案、回复章节、展品、状态。答案在有展品支撑前只是草稿。

官员常审查的要点（按 Dhanasar 和 Policy Manual 归纳，不是任何通知的原文；回复时
以你收到的通知原文为准）：

| 要件 | 可能被指出的缺口（依据） |
| --- | --- |
| National importance | 证据只证明领域重要，而非具体 endeavor 的潜在前瞻性影响（*Dhanasar* at 889）；未说明工作如何区别于该领域的其他研究、对他人开发同类技术有何影响，或缺乏采用、使用的客观证据（Policy Manual Vol. 6, Pt. F, Ch. 5, Sec. D）；只惠及雇主（同上）；信件缺乏第一手知识（同上） |
| Well positioned | 缺少计划、进展或相关方兴趣的证据（*Dhanasar* at 890）；未说明他人如何使用申请人的工作；主张未经佐证（Policy Manual Sec. D）；引用、发表、审稿未与具体进展相连 |
| Balance | 未结合申请人的事实说明 labor certification 为何不切实际、技能为何难以在其中表述、国家利益为何紧迫（*Dhanasar* at 890–91 & n.10）；以劳动力短缺代替论证（Policy Manual Sec. D） |

## 2. 期限计算

- 以**通知上印的日期**为准，回复必须在该日期前被 USCIS **收到**（received），
  不是寄出（8 CFR 103.2(a)(7)(i)：以 "actual date of receipt" 记录收件日）。
- RFE 回复期最长 12 周，**不得延期**（8 CFR 103.2(b)(8)(iv)；Policy Manual Vol. 1,
  Pt. E, Ch. 6："The maximum response time for an RFE is 12 weeks (84 days)"）。
- 邮寄送达的通知，规则上加 3 天（8 CFR 103.8(b)）。**不要自己再加**：直接用通知
  印的到期日；若你认为通知日期有误，按更早的日期执行。
- 在线提交的回复，USCIS 视为提交当日收到（Policy Manual Vol. 1, Pt. E, Ch. 6）。
- 未按期回复：可能被视为放弃（abandoned）或按现有记录拒绝（8 CFR 103.2(b)(13)(i)）。
- Premium processing 案件收到回复后的处理时限，以 USCIS premium processing 页面
  当天说明为准，不在此陈述。

**倒排内部里程碑**（填入 README）：

| 里程碑 | 建议相对时间 |
| --- | --- |
| Finding 表 + 回复地图完成 | 收到后 3–5 天 |
| 求信请求发出 | 收到后 1 周内 |
| 信件截止（cutoff） | 到期日前约 2.5 周 |
| 全文终稿 + 展品冻结 | 到期日前约 1.5 周 |
| 提交（在线）/ 交寄（快递，带追踪） | 到期日前至少 1 周 |

节假日、推荐人出差、学期末都会吃掉时间；倒排时先把这些标出来。

## 3. 只交一次，一次交全

- 8 CFR 103.2(b)(11)："All requested materials must be submitted together at one
  time"；只交一部分 "will be considered a request for a decision on the record"。
- 所以：**没有"先交一部分，后面补"**。到 cutoff 没到的信，就不进这次回复；
  全文必须在没有这封信的情况下也成立。
- USCIS 在一份 2023 年的 stakeholder Q&A 中说明（USCIS 发布，属指引而非法规；
  语境是在线递交案件）：在线递交的案件可选在线或邮寄回复，但**只能回复一次**；
  在线 RFE 入口只有一次提交机会；当时每次 RFE 回复最多上传 5 个文件，更多文件可
  同时用 "Unsolicited Evidence" 工具上传；入口在到期日关闭，事后上传的
  unsolicited evidence 不能补救逾期。来源：
  https://www.uscis.gov/sites/default/files/document/outreach-engagements/USCISCurrentIssuesSessionNAFSAAnnualConference2023QuestionsandAnswers.pdf
  （checked 2026-11-20）。**上传数量、文件大小（在线递交页面写明单文件不超过
  12MB、通常为 PDF/JPG）以当天账户界面和
  https://www.uscis.gov/file-online/tips-for-filing-forms-online 为准**。

## 4. 渠道确认（组装前做）

| 情况 | 做法 |
| --- | --- |
| 原申请在线递交，账户里能看到 RFE 回复入口 | 首选在线；按入口限制把回复合并为少数几个带书签的 PDF（brief、展品分卷） |
| 通知只给了邮寄地址或要求附 coversheet | 按通知指示邮寄，原 RFE 通知和 coversheet 放在最上面；用可追踪快递 |
| 纸质递交的案件 | 不要寄到 lockbox；按通知上的地址 |
| 任何情况 | 只选一个渠道；截图保存提交确认页 / 快递签收记录 |

在 README 的渠道检查项中记录：检查日期、账户中看到了什么、选择了什么渠道。

## 5. 回复结构：引用 → 回答 → 最少展品

每个 finding 一个小节，固定结构：

1. **逐字引用** finding（带通知页码）。
2. **第一段就回答**，一句话结论，不要先铺背景。
3. 区分**法律要件**和**事实命题**：这一段要证明的事实是什么。
4. 引用**能证明该命题的最少展品**，带页码（`[Exhibit M-1, p. 2]`）。
5. 说明每项证据的**证明力和局限**（例如：研究中使用 ≠ 部署；引用 ≠ 采用）。
6. 区分递交时已存在的事实与递交后的进展（第 7 节）。
7. 以一句话结束该要件的结论。

全文开头放一页 **Response Map**（来自 `02_Response_Map.md`），让官员一眼看到每条
finding 都有对应。

**不要**：把整份个人陈述"incorporated by reference"；堆砌泛泛的领域重要性材料；
用"杰出""开创性""第一个"之类无法证明的形容词。

## 6. 不改 endeavor（*Izummi*）

- *Matter of Izummi*, 22 I&N Dec. 169, 175：不得对已递交申请作 material change 以
  补救缺陷。
- 回复中逐字引用原 endeavor 陈述，并写明"clarifies, does not alter"。可以**澄清**
  其组成部分、实现路径、衡量标准；不能换方向、扩大范围、增加新的 endeavor。
- 如果通知暗示 endeavor 太宽，回答方式是展示原 endeavor 的具体组成和证据，而不是
  重新定义它。

## 7. 递交后证据 = 持续进展（*Katigbak*）

- 资格以递交日为准（8 CFR 103.2(b)(1)、(b)(12)；*Matter of Katigbak*, 14 I&N Dec.
  45, 49）。
- 两类新证据，分开放：
  - **递交时已存在、但当时没提交的事实**（例如递交前已有第三方运行你的代码）：
    可作为证明递交时资格的新证据，注明其原始日期。
  - **递交后发生的事**（新发表、新引用、新使用、新审稿）：只作为佐证和
    "continued progress"，每项写明日期，不能说成递交时已存在。
- 以通知写明的 priority date 作为分界线，逐项核对日期；临界日期的条目单独标出。

## 8. 新展品系列，永不改号

- 原申请展品 A–J（A 身份/身份状态、B 学位、C 雇佣、D 论文/引用、E 采用/影响、
  F 审稿、G 国家重要性背景、H 陈述与 CV、I 信件、J 奖项）**保持原编号**，
  回复中直接引用原编号。
- 新证据用新系列，从 K 开始按功能分配，例如：K = 为回复取得的信件；L = 带日期的
  递交后进展记录；M = 为回复准备的分析（采用表、方法对比）；N 或 P = 新增政府/
  政策来源。具体分配写在 `01_Response_Outline.md` 顶部的系列表里。
- 不复用、不重排已递交的编号；即使某个原展品有错，也用新展品更正并说明。
- 在 brief 末尾列 New Exhibit Index。

## 9. 求信：目标、时间线、截止

用 `04_Letter_Outreach_Plan.md`：

- **按证据功能选人**，不按头衔：
  - 实际使用过你工作的后来作者（最能回答"无人采用"）；
  - 合作者（能证明你的具体角色、持续合作和可用资源，但须披露关系）；
  - 一位无关系的领域专家（只能评价技术意义，不能证明使用或你的角色）。
- **事实信**：第一段披露关系；只写写信人亲身知道的事；区分"运行了发布的代码"
  "复现了方法""作为对比基线""只是引用"；不套 NIW 法律术语。
- 可提供一份中性的要点大纲供对方任意修改，不提供写好的推荐信让对方签字。
- 同一篇论文的多位作者不要同时联系；先联系通讯作者。
- **Cutoff**：到期日前约 2.5 周。之后到的信不进本次回复。全文每一节都不能依赖
  某封信一定到来。
- 发多少请求取决于回复率：陌生人的回复率低，节假日更低。

## 10. 把关键证据放进正文

如果通知说"没有采用证据"，而你的原记录里其实有（例如一份引用分析报告），
不要只在正文写一句"见某展品"。在正文里直接放一页表格（`05_Adoption_Table.md`）：

| 引用工作 | 独立机构 | 具体用法 | 页码 | 对应 endeavor 组成 |

并在表前一句说明：该展品已随原申请递交，但通知的证据清单未提到它。再做两张
小映射：按**通知列出的相关方类型**（院系、研究实验室、产业、开发者）分组；按
**endeavor 组成**分组，并坦白哪些组成已有第三方使用、哪些仍是研究阶段或尚无。
坦白弱项比被官员发现更有说服力。

独立性检查（每行都要过）：没有共同作者；不是你的实验室或雇主；确认对方是真的
运行/构建，而不是只引用；数字是对方新跑的还是照抄你的论文（照抄的不能当复现）。

## 11. 定稿与组装

自查清单（全部打勾才提交）：

- [ ] Response Map 覆盖通知中每一条 finding 和每一项列举因素。
- [ ] 每句事实陈述都有展品 + 页码；页码对照最终 PDF 复核过。
- [ ] 所有引文对照通知原件和法律原文逐字核对（`03_Policy_Sources.md` 记录日期）。
- [ ] Endeavor 陈述与原申请逐字一致。
- [ ] 递交后证据全部标注日期；没有把后来的事实说成递交时存在。
- [ ] 计数类数据（引用、star、下载）带快照日期，未被说成"采用"或"用户"。
- [ ] 自荐或互惠的审稿/职务如实描述或删除。
- [ ] 姓名、日期、学位名称、论文状态在全文和原申请之间没有矛盾；有不一致的
      地方附说明。
- [ ] 新展品编号不与原展品冲突；New Exhibit Index 完整。
- [ ] 隐私：仓库中的文件不含证件号、地址、薪资；提交版的 PDF 元数据已检查。
- [ ] 组装顺序：RFE 通知（及 coversheet，如要求）→ cover letter → brief（含
      Response Map）→ New Exhibit Index → 新展品 → （如需）被引用的原展品页。
- [ ] 渠道已确认（第 4 节），只提交一次，保存提交/签收证明。
- [ ] 有条件时请律师做有限范围复核。

## 12. 停止规则

- 不编造信件、用户、指标、奖项或职责。
- 不改动截图或原始文件（遮挡隐私须明确标注为 redaction）。
- 未经授权不披露雇主保密信息；涉及公开工作的知识产权归属，先核对雇主政策。
- 遇到网站阻止自动访问，停止并人工获取，不绕过。
